# Tool selection

The executable router is learning-artifacts/src/router.mjs; the broader design is learning-artifacts/docs/ARCHITECTURE.md. Representation follows the objective and observable action, not the subject or how impressive 3D looks.

| Need | Route |
|---|---|
| Language, classification, numbers, graphs, comparison | Semantic HTML and SVG |
| Many moving 2D marks or fields | Canvas with HTML controls and equivalent text |
| Rotation, depth, hidden surfaces, viewpoint | Three.js with semantic controls and an accessible explanation |
| Sequencing, emphasis, reversible presentation | GSAP; domain model remains authoritative |
| Useful custom mesh, UVs or authored asset | Background Blender Python to GLB |
| Iterative live Blender authoring | MCP after a registered server/addon round trip passes |
| Explicit MP4 request | HyperFrames, shared model, fixed scenario, paused timeline, arbitrary seeking |

Run blocking rules first, choose the first eligible representation, then compose optional tools. Missing capabilities cannot silently remove interactions or change an interactive deliverable into video. An accessible explanation does not complete a required 3D task.

Cloud defaults: software WebGL, one Blender job, one video render, local assets, no paid generators, no child accounts or telemetry. Device performance remains unmeasured until tested on intended hardware. Prefer procedural geometry for cubes, globes, and fraction bars.
